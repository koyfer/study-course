LAMP-стек: Apache, MySQL, PHP і розгортання вебзастосунку

LAMP — класичний стек для 3-рівневого вебзастосунку: Linux як ОС, Apache як вебсервер, MySQL для даних і PHP для логіки. На ньому досі працюють WordPress, Moodle і Вікіпедія.

Чого ви навчитесь#

  • Пояснити, з чого складається LAMP і чим від нього відрізняється LEMP.
  • Орієнтуватися в конфігурації Apache: httpd.conf, DocumentRoot, <Directory>, <VirtualHost>, модулі.
  • Розуміти, навіщо mod_rewrite, .htaccess і директива AllowOverride.
  • Знайти й прочитати логи Apache (ErrorLog, CustomLog).
  • Відтворити послідовність розгортання PHP-застосунку на CentOS і зробити бекап БД.
  • Розрізняти групи SQL-команд (DDL, DML, DCL) і писати базові запити: SELECT … WHERE з BETWEEN, IN, LIKE, IS NULL, а також GROUP BY і JOIN.

Що таке LAMP#

LAMP реалізує 3-рівневу архітектуру з лекції 4: клієнт (браузер) → сервер застосунку (вебсервер) → сервер БД.

Apache HTTP ServerВебсервер

Виріс із NCSA HTTPd (Роб МакКул). Назву пояснюють як «a patchy server» — сервер із латками. За статистикою зі слайдів (2018) — 43% активних сайтів.

MySQLСКБД

Створена MySQL AB (1995), у 2008 куплена Sun, у 2010 разом із Sun — Oracle. Сумісний форк — MariaDB.

PHPСкриптова мова

Расмус Лердорф, 1994. Ключові версії: PHP 5 (2004), PHP 7 (2015), PHP 8 (2020). Популярний фреймворк — Laravel.

Чому LAMP досі вивчають? У чаті лекції було гаряче обговорення «застарілості». Позиція інструктора: стек простий, дає швидкий результат і показує принципи, які потім переносяться на NGINX, Node.js чи Java/Tomcat. Близько третини сайтів працює на WordPress, тобто на LAMP. На практиці часто комбінують Apache + NGINX (NGINX спереду як проксі).

Конфігурація Apache#

Apache налаштовується директивами в текстових файлах. Головний файл — httpd.conf (у CentOS: /etc/httpd/conf/httpd.conf; у Debian/Ubuntu: /etc/apache2/apache2.conf + каталоги sites-enabled, mods-enabled). Типи файлів (MIME) читаються з mime.types (директива TypesConfig). Віртуальні хости і модулі рекомендують виносити в окремі файли.

ДирективаПризначення
DocumentRootКаталог, з якого віддаються файли. Шлях з URL додається до нього: /var/www/html + /shop/index.php
<Directory>Група директив для каталогу, його підкаталогів і файлів
<VirtualHost>Налаштування окремого сайту — кілька доменів на одному сервері
LoadModuleПідключити модуль (кожен модуль має свої директиви)
AllowOverrideЯкі директиви дозволено перевизначати в .htaccess
ErrorLog, CustomLog, LogFormatЖурнал помилок, журнал доступу та його формат
<VirtualHost *:80>
    ServerName shop.example.com
    DocumentRoot /var/www/html/opencart/upload
    <Directory /var/www/html/opencart/upload>
        AllowOverride All          # дозволити .htaccess (потрібно для mod_rewrite)
        Require all granted
    </Directory>
    ErrorLog  /var/log/httpd/shop-error.log
    CustomLog /var/log/httpd/shop-access.log combined
</VirtualHost>

Модулі

Apache має модульну архітектуру: ядро — mod_core, решта підключаються через LoadModule. Часто використовувані: ssl, rewrite, proxy, userdir, headers, php.

  • mod_rewrite — переписує URL «на льоту» за правилами на основі регулярних виразів (PCRE). Може мапити URL на файл, робити редирект або внутрішній проксі-запит. Директиви: RewriteEngine, RewriteRule, RewriteCond, RewriteBase, RewriteMap, RewriteOptions. Саме він робить «гарні» URL типу /product/42 замість index.php?route=product&id=42.
  • mod_proxy — перетворює Apache на проксі/шлюз, підтримує протоколи і алгоритми балансування навантаження.
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f        # якщо такого файла немає…
RewriteRule ^product/([0-9]+)$ index.php?id=$1 [L]   # …передати в PHP

.htaccess і AllowOverride

.htaccess («розподілений конфіг») — файл із директивами в каталозі сайту, що діє на цей каталог і всі вкладені. Потрібен, коли власник сайту не має root-доступу до сервера. Директива AllowOverride визначає, що з нього застосовувати: при None (і AllowOverrideList None) сервер навіть не шукає .htaccess, при All — дозволено все.

Логи

  • Error log (ErrorLog) — найважливіший журнал: помилки запуску, падіння скриптів, відмови в доступі. Першим дивимося сюди.
  • Access log (CustomLog) — кожен оброблений запит: IP, час, метод, URL, код статусу, розмір. Формат задає LogFormat.
tail -f /var/log/httpd/error_log           # стежити за помилками в реальному часі
grep " 500 " /var/log/httpd/access_log     # знайти запити із помилкою сервера

Практика: розгортання OpenCart на CentOS#

На лекції розгортали інтернет-магазин OpenCart 2.x. Послідовність — типова для будь-якого PHP-застосунку.

  1. Підготовка ОС (лише для навчального стенда!). Вимкнути firewalld і SELinux, підключити репозиторій EPEL, за проблем із DNS прописати nameserver 8.8.8.8 у /etc/resolv.conf.
  2. MySQL. Додати репозиторій MySQL, встановити mysql-community-server, увімкнути автозапуск і запустити, знайти тимчасовий пароль у /var/log/mysqld.log, запустити mysql_secure_installation.
  3. Користувач і БД. Створити користувача, видати права, створити БД з кодуванням UTF-8.
  4. Apache + PHP. Встановити httpd і пакети PHP (php-mysql, php-gd, php-mbstring…), увімкнути автозапуск; для mod_rewrite змінити AllowOverride None → All.
  5. Код застосунку. Завантажити архів (wget), розпакувати (unzip), скопіювати в /var/www/html, створити config.php з config-dist.php, віддати файли користувачу apache.
  6. Веб-інсталятор. Відкрити http://IP/opencart/upload/install/, ввести параметри БД; після встановлення видалити каталог install/.
# сервіси керуються через systemctl
systemctl enable --now mysqld          # автозапуск + старт (enable і start в одній команді)
systemctl status mysqld
grep password /var/log/mysqld.log      # тимчасовий пароль root
mysql_secure_installation

yum -y install httpd php php-mysql php-gd php-mbstring php-xml
systemctl enable --now httpd

cp -r opencart /var/www/html/
chmod -R 775 /var/www/html/opencart
chown -R apache:apache /var/www/html/opencart
systemctl restart httpd
CREATE USER 'shop'@'localhost' IDENTIFIED BY 'StrongPass!1';   -- локальний доступ
CREATE USER 'shop'@'%' IDENTIFIED BY 'StrongPass!1';           -- з будь-якого хоста
GRANT ALL ON opencart.* TO 'shop'@'localhost';
CREATE DATABASE opencart CHARACTER SET utf8 COLLATE utf8_bin;
SHOW DATABASES;

'user'@'localhost' і 'user'@'%' — різні облікові записи MySQL: перший підключається лише з цього ж сервера, другий — з будь-якої адреси. На слайдах права видаються як GRANT ALL ON *.* (на всі БД) — для стенда ок, для production давайте права лише на потрібну БД.

Нюанси зі слайдів

Старий OpenCart 2.x не працював з новим механізмом автентифікації MySQL 8 і з режимом sql_mode = 'MYSQL40', тому на лекції користувача переводили на mysql_native_password і правили інсталятор. Це приклад реальної DevOps-роботи: сумісність версій. Також нагадування з чату: репозиторії CentOS 7 закриті, частину пакетів доводиться брати з дзеркал — для нових серверів інструктор радить Ubuntu Server.

Резервні копії БД#

mysqldump --all-databases > dump.sql                 # усі БД
mysqldump -u root -p opencart > opencart.sql         # одна БД
mysql -u root -p opencart < opencart.sql             # відновлення

Зверніть увагу на напрямок перенаправлення з лекції 2: > — вивантажити дамп у файл, < — подати файл на вхід клієнту mysql.

SQL: мінімум, який перевіряють у тестах#

SQL (Structured Query Language) — мова роботи з реляційними БД: MySQL, PostgreSQL, MS SQL, Oracle. Команди SQL поділяють на групи:

ГрупаДля чогоКоманди
DDL — Data Definition Languageструктура: БД, таблиці, індексиCREATE, ALTER, DROP, TRUNCATE
DML — Data Manipulation Languageдані в таблицяхSELECT, INSERT, UPDATE, DELETE
DCL — Data Control Languageправа доступуGRANT, REVOKE
TCL — Transaction Control LanguageтранзакціїCOMMIT, ROLLBACK

Деякі джерела виносять SELECT в окрему групу DQL (Data Query Language). GRANT з цієї лекції — це DCL, а дамп mysqldump складається з DDL (CREATE TABLE) і DML (INSERT).

Анатомія запиту SELECT

SELECT name, price                 -- які стовпці (* — усі)
FROM product                       -- з якої таблиці
WHERE price > 100                  -- фільтр рядків
ORDER BY price DESC                -- сортування (ASC — за замовчуванням)
LIMIT 10;                          -- перші 10 рядків (MySQL, PostgreSQL)

Оператори в WHERE

ОператорПрикладВажливо
= <> != < > <= >=Id <> 5<> — стандартне «не дорівнює»
BETWEEN a AND bId BETWEEN 2 AND 4включає обидві межі; спочатку менша: BETWEEN 4 AND 2 поверне 0 рядків
IN (…)Id IN (2, 3, 4)перелік через кому; запису IN (2..4) у SQL немає — помилка синтаксису
LIKEname LIKE 'Lap%'шаблон рядка: % — будь-яка кількість символів, _ — рівно один
IS NULL / IS NOT NULLemail IS NULL= NULL не працює — завжди «невідомо»
AND OR NOTa >= 2 AND a <= 4кожна умова повна: Id >= 2 AND <= 4 — помилка
Типова задача з тесту

Для цілого Id запит WHERE Id BETWEEN 2 AND 4 еквівалентний WHERE Id >= 2 AND Id <= 4 і WHERE Id IN (2, 3, 4). Не еквівалентні: Id > 2 AND Id < 4 (лише 3), BETWEEN 4 AND 2 (порожньо), IN (2..4) і LIKE 2..4 (некоректні).

Зміна даних, агрегати, групування, JOIN

INSERT INTO category (Id, name) VALUES (5, 'Laptops');
UPDATE category SET name = 'Notebooks' WHERE Id = 5;   -- без WHERE зміниться ВСЯ таблиця
DELETE FROM category WHERE Id = 5;                     -- без WHERE видалить усі рядки

SELECT category_id, COUNT(*) AS cnt, AVG(price)        -- COUNT SUM AVG MIN MAX
FROM product
GROUP BY category_id                                    -- групи рядків
HAVING COUNT(*) > 10;                                  -- фільтр уже по групах

SELECT p.name, c.name
FROM product p
INNER JOIN category c ON p.category_id = c.Id;          -- лише рядки з парою в обох таблицях
  • WHERE фільтрує рядки до групування, HAVING — групи після GROUP BY.
  • INNER JOIN — лише збіги; LEFT JOIN — усі рядки лівої таблиці (+ NULL, якщо пари немає); RIGHT JOIN — навпаки.
  • PRIMARY KEY — унікальний ідентифікатор рядка; FOREIGN KEY — посилання на ключ іншої таблиці.
  • DELETE (DML) видаляє рядки, можна з WHERE; TRUNCATE (DDL) швидко очищає всю таблицю; DROP (DDL) видаляє саму таблицю разом зі структурою.

Типові помилки#

WHERE email = NULL знайде записи без email.
З NULL порівнюють лише через IS NULL / IS NOT NULL.
BETWEEN не включає межі, або порядок меж не важливий.
BETWEEN 2 AND 4 включає 2 і 4; нижня межа має бути першою.
Правила .htaccess «не працюють», хоча файл на місці.
Перевірте AllowOverride для каталогу (при None файл ігнорується) і чи завантажено mod_rewrite. Після змін у конфігу — systemctl restart httpd.
Сайт видає 403/500 — одразу chmod -R 777.
Спершу error_log. Зазвичай досить віддати файли користувачу вебсервера (chown -R apache:apache) з правами 755/644.
Вимкнути firewall і SELinux на production, як на лабі.
На production відкривають лише потрібні порти (80/443) і налаштовують SELinux-контексти, а не вимикають захист.
Забути видалити install/ після встановлення CMS.
Каталог інсталятора дозволяє перевстановити сайт і перезаписати БД — його видаляють одразу.
