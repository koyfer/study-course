Bash: скрипти, змінні, умови, цикли та функції

Bash — «клей» між утилітами Linux. Він є майже на кожному сервері, тому deployment-скрипти й автоматизацію рутинних дій найчастіше пишуть саме на ньому.

Чого ви навчитесь#

  • Створити і запустити bash-скрипт (shebang, права, позиційні параметри).
  • Правильно працювати зі змінними: присвоєння без пробілів, різниця "подвійних" і 'одинарних' лапок.
  • Використовувати спецзмінні $0 $1 $# $@ $? $$ та підстановку команд.
  • Писати умови if [ … ] з правильними операторами для чисел і рядків.
  • Писати цикли for, while, until і функції з local-змінними.
  • Розуміти різницю між ./script.sh, bash script.sh і source script.sh, коди виходу і «суворий режим» set -euo pipefail.
  • Використовувати розкриття параметрів (${var:-default}, ${f%.txt}), масиви, [[ ]] і (( )).
  • Читати файли рядок за рядком, розбирати опції через getopts, прибирати за собою через trap.
  • Ставити скрипти в cron і писати практичні скрипти: бекап з ротацією, моніторинг диска, перевірку сайтів.
  • Передбачати результат рядка bash, знаючи порядок розкриттів і роль лапок.
  • Писати скрипти з перевіркою аргументів, retry, меню, обробкою CSV і безпечним прибиранням через trap.

Оболонки і чому bash#

Shell (оболонка) — програма, що приймає ваші команди і запускає їх. У Linux є багато оболонок: sh (Bourne), csh, ksh, tcsh, zsh, але найпопулярніша — bash (Bourne Again Shell). Вона сумісна з sh, взяла найкраще з ksh і csh та відповідає стандарту POSIX.

Bash чи Python?

Питання з чату лекції. Bash «склеює» POSIX-утиліти (grep, cp, systemctl…) і є майже в будь-якій системі, а Python може бути не встановлений (у мінімальних образах на кшталт Alpine навіть bash буває відсутній — там sh). Для коротких сценаріїв розгортання — bash, для складної логіки й обробки даних — Python.

Перший скрипт#

Перший рядок — shebang #!/bin/bash: він каже ОС, яким інтерпретатором виконувати файл.

#!/bin/bash
# hello.sh — коментар починається з #
name="DevOps"
echo "Hello, $name! Сьогодні: $(date +%F)"
chmod +x hello.sh     # дати право на виконання
./hello.sh            # запуск із поточного каталогу
bash hello.sh         # або явно через інтерпретатор

Різниця між підоболонкою і source принципова. Дочірній процес отримує копію змінних середовища; усе, що скрипт змінить (змінні, поточний каталог), зникне після його завершення. source виконує команди у вашій оболонці, тож зміни лишаються — тому так перечитують ~/.bashrc або підвантажують файл зі змінними:

$ cat setenv.sh
export APP_ENV=staging
cd /opt/app

$ ./setenv.sh ; echo "$APP_ENV" ; pwd     # порожньо; каталог не змінився
$ source setenv.sh ; echo "$APP_ENV" ; pwd   # staging; /opt/app

Shebang

  • #!/bin/bash — конкретний шлях до bash.
  • #!/usr/bin/env bash — знайти bash у PATH; переносніше (macOS, NixOS, bash у /usr/local/bin).
  • #!/bin/sh — POSIX-оболонка. У Debian/Ubuntu це dash, який не знає bash-розширень ([[ ]], масиви, {1..5}): скрипт з bash-синтаксисом під sh впаде з помилками.
  • Shebang має бути першим рядком, без пробілів перед #!. Файл, створений у Windows, може мати кінці рядків \r\n — тоді Linux шукатиме інтерпретатор bash\r і видасть bad interpreter. Лікується sed -i 's/\r$//' script.sh або dos2unix.

Коди завершення: exit

Скрипт, як і будь-яка команда, повертає код виходу: exit 0 — успіх, exit 1 (або 2–255) — помилка. Без явного exit повертається код останньої виконаної команди. CI-системи (Jenkins, GitHub Actions) вважають крок проваленим саме за ненульовим кодом.

КодЗначення за домовленістю
0успіх
1загальна помилка
2неправильне використання (помилкові аргументи, синтаксис)
126команду знайдено, але вона не виконувана (немає права x)
127команду не знайдено (command not found)
128 + Nпроцес завершено сигналом N: 130 — Ctrl+C (SIGINT, 2), 137 — kill -9 (9)

«Суворий режим» і налагодження

#!/usr/bin/env bash
set -euo pipefail
# -e          вийти, щойно будь-яка команда поверне ненульовий код
# -u          помилка при зверненні до неіснуючої змінної (захист від rm -rf "$DIR/" з порожнім DIR)
# -o pipefail код конвеєра = код першої впалої команди, а не лише останньої

Без pipefail конвеєр false | true повертає 0, тож помилку в середині curl … | tar xz ніхто не помітить. Нюанс set -e: він не спрацьовує для команд в умовах if, у лівій частині &&/|| — це навмисно.

bash -n script.sh     # перевірити синтаксис, не виконуючи
bash -x script.sh     # трасування: кожна команда друкується з + після підстановок
set -x ... set +x     # увімкнути / вимкнути трасування на ділянці скрипта
shellcheck script.sh  # статичний аналізатор: знаходить незахищені лапками змінні, помилки в [ ] тощо

Змінні та лапки#

  • Змінні не оголошуються — створюються при присвоєнні. Значення завжди зберігаються як рядки; арифметика перетворює їх на числа.
  • Присвоєння — без пробілів навколо =: count=0. Звернення — через $: $count або ${count}.
  • Тип не фіксований: count=0, потім count=Sunday — легально, але погана практика. Одна змінна — один тип даних.
  • \ — символ екранування: зберігає буквальне значення наступного символу (\$ виведе знак долара).

"Подвійні лапки"

Змінні підставляються.

var="test string"
echo "Value: $var"
# Value: test string

'Одинарні лапки'

Усе буквально, без підстановки.

var="test string"
echo 'Value: $var'
# Value: $var

Рядки з пробілами чи спецсимволами обов'язково беріть у лапки. Ввести значення з клавіатури — команда read:

read -p "Введіть ім'я: " user
echo "Привіт, $user"

Масиви

Як bash читає рядок: порядок розкриттів крок за кроком#

Більшість «дивних» помилок у скриптах пояснюються тим, що bash перетворює рядок команди до запуску, у суворому порядку. Знаючи цей порядок, ви передбачите результат будь-якого рядка.

  1. Розбиття на слова і токени з урахуванням лапок; розпізнаються оператори |, &&, ;, >.
  2. Розкриття фігурних дужок (brace expansion): file{1..3}.txt → file1.txt file2.txt file3.txt.
  3. Тильда: ~ → /home/student, ~bob → /home/bob.
  4. Параметри і змінні: $name, ${name:-default}.
  5. Підстановка команд: $(date +%F) → 2026-11-10.
  6. Арифметика: $((2+3)) → 5.
  7. Розбиття на слова (word splitting) результатів кроків 4–6, якщо вони не в лапках — за символами з IFS (пробіл, табуляція, новий рядок).
  8. Шаблони імен (globbing): *.log → список файлів, якщо слово не в лапках.
  9. Видалення лапок: самі лапки зникають, лишається їхній вміст.

Розібраний приклад 1: чому rm $file небезпечний

file="my report.txt"
rm $file          # крок 7 ділить "my report.txt" на два слова → rm my report.txt
                  # rm: cannot remove 'my': No such file or directory
                  # rm: cannot remove 'report.txt': ...  (або видалить ІНШИЙ файл report.txt!)
rm "$file"        # у лапках крок 7 пропускається → rm 'my report.txt'

Розібраний приклад 2: змінна з зірочкою

pattern="*.log"
echo $pattern     # крок 8 розкриває шаблон → app.log error.log
echo "$pattern"   # у лапках шаблон не розкривається → *.log

Розібраний приклад 3: фігурні дужки йдуть раніше за змінні

n=3
echo {1..$n}      # {1..$n} — brace expansion (крок 2) ще не знає значення n → друкує {1..3}
echo $(seq 1 $n)  # 1 2 3 — seq отримує вже розкрите значення
for ((i=1; i<=n; i++)); do echo $i; done   # 1 2 3 — арифметичний цикл

Арифметика#

Вирази обчислюються через $(( вираз )) (старий варіант — $[ вираз ]) або команду let. Bash працює лише з цілими числами — дробових немає.

echo $(( 100 / 3 ))         # 33 — ціла частина!
myvar="56"
echo $(( myvar + 12 ))       # 68
myvar=$(( myvar + 1 ))       # інкремент
let COUNTER=COUNTER+1        # те саме через let

Умови: if і вирази test#

if [ "$myvar" -eq 3 ]; then
    echo "myvar = 3 як число"
elif [ "$myvar" = "3" ]; then
    echo "myvar = 3 як рядок"
else
    echo "інше"
fi

if [ -z "$1" ]; then echo "Порожній параметр"; exit 1; fi
Синтаксис

[ — це команда, тому пробіли обов'язкові: після [, перед ] і навколо операторів. [ $a -eq 1 ] ✓, [$a -eq 1] ✗. Якщо then/do на тому ж рядку — перед ним ставте ;.

Цикли детальніше: діапазони, читання файлів, break і continue#

Різні форми for

for i in 1 2 3 4 5; do echo $i; done            # явний список
for i in {1..5}; do echo $i; done               # діапазон (розкриття дужок)
for i in {0..20..5}; do echo $i; done           # з кроком: 0 5 10 15 20
for i in $(seq 1 5); do echo $i; done           # через seq (діапазон можна задати змінними)
for (( i=0; i<5; i++ )); do echo $i; done       # C-стиль: 0..4
for arg in "$@"; do echo "Аргумент: $arg"; done # усі аргументи скрипта
for f in *.log; do gzip "$f"; done              # файли за шаблоном
for u in $(cut -d: -f1 /etc/passwd); do …; done  # вивід команди (розбивається за пробілами!)

Функції та область видимості#

За замовчуванням змінні в bash глобальні: функція, що змінює myvar, змінить її для всього скрипта. Щоб змінна жила лише у функції — оголосіть її local.

Без local

myvar="hello"
myfunc() {
  myvar="one two three"
  for x in $myvar; do echo $x; done
}
myfunc
echo "$myvar / $x"
# one two three / three

З local

myvar="hello"
myfunc() {
  local x
  local myvar="one two three"
  for x in $myvar; do echo $x; done
}
myfunc
echo "$myvar / $x"
# hello /   (x порожня)

Що повертає функція? Питання з чату: return N повертає лише код завершення 0–255 (читається через $?), як у будь-якої команди. Щоб повернути дані, функція виводить їх через echo, а викликач забирає через $(…):

get_ip() { hostname -I | awk '{print $1}'; }
is_root() { [ "$(id -u)" -eq 0 ]; }    # код 0 = «істина»

ip=$(get_ip)
if is_root; then echo "root on $ip"; else echo "not root"; fi

Ввід, вивід, опції скрипта і trap#

read і printf

read -p "Ім'я: " name                 # з підказкою
read -s -p "Пароль: " pass; echo      # -s: не показувати ввід
read -t 10 -p "Продовжити? [y/N] " ans || ans=n   # -t: тайм-аут 10 с
read -r a b c <<< "1 2 3"             # розбити рядок на змінні

printf "%-10s %5d\n" "nginx" 812     # форматований вивід: ширина колонок, числа

echo -e "рядок1\nрядок2"             # -e: інтерпретувати \n, \t
echo "Помилка!" >&2                  # повідомлення про помилку — у stderr

Дробові обчислення: echo "scale=2; 7/2" | bc → 3.50 або awk 'BEGIN{print 7/2}' → 3.5.

Розбір опцій: getopts

#!/usr/bin/env bash
# ./backup.sh -d /var/www -k 7 -v
dir=/var/www; keep=5; verbose=0
while getopts "d:k:vh" opt; do          # двокрапка після літери = опція зі значенням
    case $opt in
        d) dir=$OPTARG ;;
        k) keep=$OPTARG ;;
        v) verbose=1 ;;
        h) echo "Usage: $0 [-d dir] [-k days] [-v]"; exit 0 ;;
        *) exit 2 ;;
    esac
done
shift $((OPTIND - 1))                    # прибрати оброблені опції; решта — у "$@"
(( verbose )) && echo "dir=$dir keep=$keep"

shift

shift зсуває позиційні параметри вліво: $2 стає $1, а $# зменшується на 1. Зручно для обробки аргументів у циклі while (( $# )); do …; shift; done.

case "$answer" in

  [Nn]*)       echo "Скасовано"; exit 0 ;;
  "")          echo "Порожня відповідь" ;;
  *)           echo "Не зрозумів" ;;
esac
case "$file" in
  *.tar.gz|*.tgz) tar -xzf "$file" ;;

Обробка тексту: grep, sed, awk, cut

grep -c "ERROR" app.log                      # скільки рядків з ERROR
sed 's/http:/https:/g' site.conf             # замінити текст (вивід на екран)
sed -i 's/8080/80/' app.conf                 # -i — змінити файл на місці
awk '{print $1}' access.log | sort | uniq -c | sort -nr | head   # топ IP-адрес у лозі
cut -d: -f1 /etc/passwd                      # лише імена користувачів

sed, awk, cut, sort, uniq детально розібрано в лекції 2 (розділ «Обробка тексту в конвеєрах»). Короткі правила для awk: $1, $2 — поля рядка (за замовчуванням розділені пробілами), -F: — інший роздільник, NR — номер рядка, NF — кількість полів, $NF — останнє поле.

awk -F: '$3 >= 1000 {print $1, $6}' /etc/passwd        # звичайні користувачі та їхні домашні каталоги
awk '{sum += $10} END {print sum/1024/1024 " MB"}' access.log   # сумарний обсяг відповідей
sed -n '/BEGIN/,/END/p' file                          # рядки між маркерами
sed -i.bak 's/^PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config   # змінити з резервною копією .bak

Чому скрипт працює вручну, але не в cron

Cron запускає команди з мінімальним середовищем: короткий PATH (часто лише /usr/bin:/bin), поточний каталог — домашній, без змінних з ~/.bashrc. Тому в crontab пишіть абсолютні шляхи до скриптів і програм, задавайте потрібні змінні у скрипті й обов'язково перенаправляйте вивід у лог (>> /var/log/job.log 2>&1) — інакше помилок не побачите. Знак % у crontab має спеціальне значення, його екранують: date +\%F.

Альтернатива cron у сучасних дистрибутивах — systemd timers (systemctl list-timers): логи в journald, залежності від інших служб, пропущені запуски наздоганяються після ввімкнення.

Практика: мінімальний deployment-скрипт#

Результат курсу — уміти написати bash-скрипт розгортання. Ось шаблон, що поєднує все з лекції: аргументи, перевірки, функції, коди завершення.

#!/bin/bash
# deploy.sh <git-url> [branch]  — розгорнути сайт у /var/www/html/app
set -e                                   # зупинитись на першій помилці

REPO="$1"; BRANCH="${2:-main}"; TARGET=/var/www/html/app

log() { echo "[$(date +%T)] $*"; }

if [ $# -lt 1 ]; then
    echo "Usage: $0 <git-url> [branch]"; exit 1
fi
if [ "$(id -u)" -ne 0 ]; then
    echo "Run as root (sudo)"; exit 1
fi

if [ -d "$TARGET/.git" ]; then
    log "Оновлюю код ($BRANCH)"
    git -C "$TARGET" pull origin "$BRANCH"
else
    log "Клоную $REPO"
    git clone -b "$BRANCH" "$REPO" "$TARGET"
fi

chown -R apache:apache "$TARGET"
systemctl restart httpd
log "Готово, код завершення: $?"

Кожна задача — з розв'язком і поясненням рядків, на яких зазвичай помиляються. Запускайте їх у будь-якому Linux або WSL: nano task.sh, вставити код, chmod +x task.sh, ./task.sh.

1. Привітання з аргументом і значенням за замовчуванням

#!/usr/bin/env bash

>&2 направляє текст у потік помилок, тож його не «з'їсть» перенаправлення виводу. -- захищає від імен файлів, що починаються з дефіса. Різні коди виходу (1, 2) дозволяють зовнішньому скрипту зрозуміти, що саме пішло не так.

3. Сума всіх чисел-аргументів

#!/usr/bin/env bash

for n in "$@"; do
    [[ $n =~ ^-?[0-9]+$ ]] || { echo "Не число: $n" >&2; exit 1; }
    (( sum += n ))
done
echo "Сума: $sum"
# ./sum.sh 4 10 -3 → Сума: 11

=~ перевіряє регулярний вираз (лише в [[ ]]). Арифметика в (( )) працює з цілими; дробові числа рахують через bc або awk: echo "3.5 + 1.2" | bc.

4. Масове перейменування *.jpeg → *.jpg

#!/usr/bin/env bash
shopt -s nullglob                   # якщо файлів немає — цикл не виконається жодного разу
for f in *.jpeg; do
    mv -n -- "$f" "${f%.jpeg}.jpg"  # ${f%.jpeg} відрізає суфікс .jpeg
done

Без nullglob при відсутності файлів цикл отримає буквальний рядок *.jpeg і mv видасть помилку. -n не перезапише файл, якщо photo.jpg уже існує.

5. Перевірка місця на диску з алертом

#!/usr/bin/env bash
threshold=85
df -P -x tmpfs | tail -n +2 | while read -r fs size used avail pct mount; do
    usage=${pct%\%}                       # "91%" → 91
    if (( usage >= threshold )); then
        echo "$(date '+%F %T') ALERT: $mount заповнено на $usage%" | tee -a /var/log/disk-alert.log
    fi
done

df -P дає стабільний формат «один рядок — одна ФС», tail -n +2 пропускає заголовок, read -r розкладає рядок по змінних. Додайте до cron: */15 * * * * /opt/scripts/disk.sh — перевірка кожні 15 хвилин.

6. Повторні спроби (retry) для нестабільної команди

#!/usr/bin/env bash
retry() {
    local tries=$1; shift
    local i
    for (( i=1; i<=tries; i++ )); do
        "$@" && return 0                 # успіх — виходимо з функції з кодом 0
        echo "Спроба $i з $tries не вдалась, чекаю $((i*2)) с" >&2
        sleep $((i*2))
    done
    return 1
}
retry 5 curl -fsS https://example.com/health -o /dev/null || echo "Сервіс недоступний"

local робить змінні видимими лише всередині функції. shift прибирає перший аргумент (кількість спроб), і в "$@" лишається сама команда. curl -f повертає ненульовий код на HTTP 4xx/5xx.

7. Меню через select і case

#!/usr/bin/env bash
PS3="Оберіть дію: "

done

8. Аналіз CSV: середня зарплата за відділами

# staff.csv:
# name,dept,salary
# Ann,dev,3000
# Bob,ops,2500
# Eve,dev,3600
awk -F, 'NR>1 { s[$2]+=$3; c[$2]++ } END { for (d in s) printf "%s %.0f\n", d, s[d]/c[d] }' staff.csv
# dev 3300
# ops 2500

-F, — роздільник кома, NR>1 пропускає заголовок, масиви s і c накопичують суму і кількість за ключем-відділом.

9. Перевірка, які хости в підмережі відповідають на ping (паралельно)

#!/usr/bin/env bash
net=${1:-192.168.1}
for i in $(seq 1 254); do
    ( ping -c1 -W1 "$net.$i" &>/dev/null && echo "$net.$i живий" ) &
done
wait                                  # дочекатися всіх фонових процесів

Кожен ping запускається у фоні (&) у підоболонці ( ), тому 254 перевірки займають секунду, а не чотири хвилини. wait не дає скрипту завершитись раніше.

10. Безпечний скрипт розгортання з тимчасовим каталогом і прибиранням

#!/usr/bin/env bash
set -euo pipefail                         # зупинка на помилці, незадана змінна = помилка, помилка в pipe = помилка
tmp=$(mktemp -d)
trap 'rm -rf "$tmp"' EXIT                 # прибирання за будь-якого виходу, навіть після помилки

version="${1:?Вкажіть версію, напр. v2.14.0}"   # немає аргументу → повідомлення і вихід
git clone --depth 1 --branch "$version" https://github.com/acme/shop.git "$tmp/shop"
rsync -a --delete --exclude .git "$tmp/shop/" /var/www/shop/
sudo systemctl reload php-fpm
echo "Розгорнуто $version о $(date '+%F %T')"
РядокНавіщо
set -eякщо git clone впаде, скрипт зупиниться, а не скопіює порожній каталог поверх сайту
set -uопечатка в імені змінної ($versoin) дасть помилку, а не порожній рядок
set -o pipefailкод помилки будь-якої команди в pipe, а не лише останньої
mktemp -dунікальний тимчасовий каталог, без конфліктів між запусками
trap ... EXITгарантоване прибирання
${1:?msg}обов'язковий аргумент з поясненням

Як налагоджувати скрипт

bash -n deploy.sh       # перевірити синтаксис, нічого не виконуючи

Типові помилки#

Скрипт, запущений як ./setenv.sh, змінить змінні й каталог поточного терміналу.
Він працює в дочірньому процесі, і зміни зникають. Щоб змінити поточну оболонку — source setenv.sh або . setenv.sh.
[ "$a" > "$b" ] порівнює рядки.
У [ ] знак > — перенаправлення у файл. Пишіть [[ $a > $b ]] або [ "$a" \> "$b" ]; для чисел — -gt або (( a > b )).
for i in {1..$n} пройде від 1 до n.
Розкриття дужок відбувається до підстановки змінних. Використовуйте seq 1 "$n" або for ((i=1; i<=n; i++)).
for line in $(cat file) читає файл по рядках.
Він розбиває текст за будь-якими пробілами. По рядках: while IFS= read -r line; do …; done < file.
Скрипт з #!/bin/sh може використовувати [[ ]] і масиви.
У Debian/Ubuntu sh — це dash без bash-розширень. Для них потрібен #!/bin/bash.
Задача в cron бачить той самий PATH, що й ваш термінал.
Середовище cron мінімальне. Пишіть абсолютні шляхи і перенаправляйте вивід у лог.
name = "Ivan" — з пробілами.
Bash сприйме name як команду. Правильно: name="Ivan".
[ "$a" = 10 ] для порівняння чисел / -eq для рядків.
Числа: -eq -ne -lt -le -gt -ge. Рядки: = != -z -n. «010» і «10» рівні як числа, але не як рядки.
Змінна без лапок: [ -z $1 ], rm $file.
Якщо значення порожнє або з пробілами — синтаксична помилка чи видалення не того. Пишіть "$1", "$file".
echo $(( 7 / 2 )) дасть 3.5.
Bash рахує лише цілі: результат 3. Для дробів — bc або awk.
return "текст" поверне рядок із функції.
return — тільки код 0–255. Дані — через echo і $(func).
