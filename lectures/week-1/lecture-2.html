Linux: командний рядок, файлова система, користувачі, права, процеси

Linux — ОС більшості серверів і контейнерів. Тут зібрано все, що перевіряє тест Linux CLI: кожна команда з опціями, розбором схожих неправильних варіантів і реальними прикладами, які знадобляться на сервері.

Чого ви навчитесь#

  • Розуміти, з чого складається Linux (ядро, оболонка, утиліти, дистрибутив) і як читати запрошення командного рядка.
  • Знаходити довідку будь-якою з п'яти способів: man, --help, help, info, apropos, і знати, які «способи» лише виглядають правильними.
  • Орієнтуватися в дереві каталогів за стандартом FHS: де конфіги, програми, логи, спільні файли, пристрої.
  • Вільно працювати зі шляхами (., .., ~, абсолютні й відносні) і шаблонами (*, ?, [ ], { }).
  • Створювати, копіювати, переміщувати, перейменовувати і видаляти файли та каталоги, розрізняючи всі варіанти rm, rmdir, mkdir -p.
  • Переглядати і шукати: cat, less, head, tail -f, find, locate, grep.
  • Розуміти inode, жорсткі й символічні посилання, змінні середовища і PATH.
  • Комбінувати команди через pipe, перенаправлення та ланцюжки.
  • Керувати користувачами, групами, правами (chmod числом і символами, umask, SUID/SGID/sticky).
  • Стежити за процесами, пам'яттю, диском, службами й логами; встановлювати пакети; працювати з архівами і SSH.

Що таке Linux і чому саме він#

Операційна система (ОС) керує залізом і дає програмам спільні сервіси: процеси, пам'ять, файли, мережу, користувачів. Linux належить до сімейства Unix-подібних (*nix) систем. Ядро анонсував Лінус Торвальдс у 1991 році; з 1992 воно поширюється за ліцензією GNU GPL.

З чого складається «Linux»

Слово «Linux» у побуті означає цілу систему, але технічно це лише ядро. Те, з чим ви працюєте в терміналі, — це кілька шарів:

KernelЯдро

Керує процесами, пам'яттю, драйверами, файловими системами, мережею. Програми звертаються до нього через системні виклики. Версія: uname -r.

ShellОболонка

Програма, що читає ваші команди і запускає їх: bash, sh, zsh. Поточна: echo $SHELL (оболонка входу) або echo $0.

GNU utilitiesУтиліти

ls, cp, grep, tar… — окремі програми-файли в /usr/bin. Тому кажуть «GNU/Linux».

DistributionДистрибутив

Ядро + утиліти + пакетний менеджер + налаштування: Ubuntu, Debian, RHEL, CentOS, Fedora, Alpine.

  • Безкоштовна і з відкритим кодом. Немає ліцензій на кожен сервер.
  • Домінує на серверах і в хмарах: більшість вебсерверів, майже всі контейнери Docker і вузли Kubernetes працюють на Linux. Android теж побудований на ядрі Linux.
  • Можна працювати без графічного інтерфейсу — тільки термінал. Для сервера це економія ресурсів і менша поверхня атаки.

Термінал, оболонка і синтаксис команди#

Термінал (terminal emulator) — вікно, у якому ви набираєте текст. Оболонка (shell) — програма всередині нього, яка розбирає рядок і запускає команди. Найпоширеніша оболонка — bash (Bourne Again SHell). Коли ви підключаєтесь до сервера по SSH, термінал у вас локальний, а оболонка працює на сервері.

root@web01:/etc#                   # root: символ # замість $

Анатомія команди

ls  -l -a  --human-readable  /var/log
#│   └─┬─┘  └──────┬──────┘   └──┬───┘
#│  короткі   довга опція      аргумент (з чим працювати)
#└─ ім'я команди (програма /usr/bin/ls або вбудована команда оболонки)
  • Короткі опції починаються з одного дефіса і зазвичай складаються з однієї літери: -l. Їх можна об'єднувати: ls -l -a -h = ls -lah.
  • Довгі опції починаються з двох дефісів: --all, --human-readable. Об'єднувати їх не можна.
  • Опції з значенням: head -n 5 file, head -n5 file або head --lines=5 file — однаково.
  • Аргументи — файли, каталоги, рядки. Порядок важливий: у cp, mv, ln спочатку джерело, потім призначення.
  • Подвійний дефіс -- означає «опції скінчились»: rm -- -file.txt видалить файл, ім'я якого починається з дефіса.
  • Пробіл — роздільник. Ім'я з пробілом беріть у лапки: cd "My Documents" або екрануйте: cd My\ Documents.

Як читати man-сторінку

  • Розділи сторінки: NAME (назва і опис), SYNOPSIS (синтаксис: [ ] — необов'язкове, ... — можна повторювати), DESCRIPTION (опції), EXAMPLES, SEE ALSO.
  • Навігація така сама, як у less: пробіл — сторінка вниз, b — вгору, /слово — пошук, n — наступний збіг, q — вихід.
  • Посібник поділено на секції: 1 — команди користувача, 5 — формати файлів, 8 — команди адміністратора. man passwd покаже команду, а man 5 passwd — формат файла /etc/passwd.
Пастки тесту

<command> /? — це довідка у Windows (cmd), у Linux /? сприйметься як аргумент-шлях. <command> ? — у bash ? є шаблоном «один будь-який символ», а не запитом довідки. Команд guide і manual у Linux немає. Правильні способи: man, --help, help (для вбудованих), info, whatis, apropos.

Структура каталогів (FHS)#

У Linux «майже все — файл»: звичайні файли, каталоги, пристрої (/dev/sda), інформація про процеси (/proc), навіть більшість команд — програми-файли. Розташування каталогів описує стандарт FHS (Filesystem Hierarchy Standard), тому на будь-якому дистрибутиві конфіги шукають в одному місці.

У сучасних дистрибутивах (Ubuntu 20.04+, RHEL 8+) /bin, /sbin і /lib — це символічні посилання на /usr/bin, /usr/sbin, /usr/lib (так звана «злита /usr»). Тому ls можна знайти і як /bin/ls, і як /usr/bin/ls.

Як відповідати на питання «який каталог містить…»

Системні конфігурації → /etc. Виконувані файли → /bin, /usr/bin (адміністративні → /sbin). Спільні (shared) файли → /usr/share; спільні бібліотеки → /lib, /usr/lib. Логи → /var/log. Тимчасові → /tmp. Пристрої → /dev. Інформація про процеси і ядро → /proc. Домашній каталог root → /root, інших → /home. Завантаження → /boot.

Шляхи: абсолютні, відносні, ., .., ~#

Абсолютний шлях починається з / і описує розташування від кореня — він однаковий, хоч би де ви були: /home/user1/docs/cv.txt. Відносний шлях не починається з / і рахується від поточного каталогу: якщо ви в /home/user1, то docs/cv.txt — той самий файл.

~домашній каталог поточного користувача (значення $HOME)~/data = /home/user1/data

Кожен каталог фізично містить записи . і .. — їх видно в ls -a. Тому cd . нічого не змінює (переходить у той самий каталог), а cd .. піднімається на рівень вище. Скісна риска в кінці (./, ../) лише підкреслює, що це каталог: cd ./ = cd ., cd ../ = cd ...

Розбір питання: «перейти в каталог user2 з домашнього каталогу user1»

Ви в /home/user1, доступ до /home/user2 є. Спрацюють усі ці варіанти, бо вони ведуть в одне місце різними шляхами:

cd /home/user2      # абсолютний шлях
cd ../user2         # відносний: вгору до /home, потім у user2
cd ~user2           # домашній каталог користувача user2
cd ~/../user2       # ~ = /home/user1, далі вгору і в user2

Не спрацюють: cd user2 (шукає /home/user1/user2), cd /user2 (шукає в корені), cd ..\user2 (зворотна риска — синтаксис Windows; bash прибере \ як екранування і шукатиме ..user2), cd../user2 без пробілу (bash шукатиме команду з назвою cd../user2 і видасть command not found).

Типові задачі з ls

ls -p | grep -v /     # лише файли (прибрати рядки з / у кінці)

ls -ltr /var/log      # найсвіжіші логи внизу
Пастки тесту з ls

«Показати лише файли і каталоги» — звичайний ls (без -a, щоб не було прихованих і службових ./..). Якщо треба розрізнити тип — ls -F або ls -l. «Файли на літеру F» — ls F*, але не ls *F (це «закінчуються на F»), не ls F? (рівно два символи) і не ls -F (це опція позначення типів). У Windows аналог — dir; у Linux такої команди за замовчуванням або немає, або вона не є стандартною відповіддю.

Шаблони імен (globbing) і розкриття фігурних дужок#

Шаблони розкриває оболонка ще до запуску команди: ls *.txt перетворюється на ls a.txt b.txt c.txt. Тому шаблони працюють з будь-якою командою: cp, rm, mv, cat.

Копіювання, переміщення, перейменування#

cp — копіювати

cp text.t info.t              # копія файла під новим іменем; text.t лишається
cp text.t ~/backup/           # копія в інший каталог з тим самим іменем
cp a.txt b.txt docs/          # кілька файлів у каталог (останній аргумент — каталог)
cp -r project project_bak     # каталог з усім вмістом (-r або -R, recursive)
cp -i text.t info.t           # -i: спитати перед перезаписом існуючого info.t
cp -n text.t info.t           # -n: ніколи не перезаписувати
cp -u src/* dst/              # -u: копіювати, лише якщо джерело новіше
cp -p config.ini /tmp/        # -p: зберегти права, власника, час
cp -a /var/www /backup/www    # -a (archive) = -r + -p + посилання як посилання: для бекапів
cp -v *.conf /etc/app/        # -v: друкувати, що скопійовано

Без -r каталог не копіюється: cp: -r not specified; omitting directory. Існуючий файл призначення cp перезаписує мовчки.

Інші способи отримати копію вмісту: cat text.t > info.t (вміст переходить, але права і час — ні; новий файл отримає типові права), dd if=text.t of=info.t, rsync text.t info.t. А от copy — команда Windows; mv перемістить, а не скопіює; ln створить посилання, а не незалежну копію.

mv — перемістити або перейменувати

У Linux немає окремої команди «перейменувати»: перейменування — це переміщення в той самий каталог під новим іменем.

mv text.t info.t              # перейменувати: text.t зникає, з'являється info.t
mv text.t ~/                  # перенести в домашній каталог (ім'я лишається)
mv text.t $HOME/              # те саме через змінну
mv text.t /home/user/         # те саме абсолютним шляхом (якщо ваш логін user)
mv text.t ~/notes.txt         # перенести і одразу перейменувати
mv *.jpg photos/              # кілька файлів у каталог
mv old_dir new_dir            # каталоги переміщуються без -r
mv -i a b                     # спитати перед перезаписом
mv -n a b                     # не перезаписувати
  • Якщо призначення — існуючий каталог, файл переїде всередину. Якщо такого каталогу немає — файл буде перейменовано. Тому mv text.t backup дає різний результат залежно від того, чи є каталог backup. Скісна риска в кінці (backup/) захищає: якщо каталогу немає, буде помилка, а не перейменування.
  • У межах однієї файлової системи mv не копіює дані, а лише змінює запис у каталозі, тому навіть гігабайтний файл переміщується миттєво.
  • rename існує як окрема утиліта для масового перейменування за шаблоном (rename 's/\.txt$/.md/' *.txt), але синтаксис відрізняється в різних дистрибутивах. Базова відповідь на «як перейменувати» — mv.
Пастка: $USER vs $HOME

mv text.t $HOME/ → у домашній каталог (наприклад, /home/anna). mv text.t $USER/ → $USER містить лише ім'я anna, тож це відносний шлях anna/ у поточному каталозі. Майже завжди такого каталогу немає, і команда видасть помилку.

Inode, жорсткі й символічні посилання#

Щоб зрозуміти посилання, треба знати, як файл зберігається на диску. Файл складається з трьох частин:

  • Блоки даних — сам вміст.
  • Inode (index node) — службовий запис із номером: розмір, власник, права, час, адреси блоків даних і лічильник посилань. Імені файла в inode немає.
  • Запис у каталозі — пара «ім'я → номер inode». Каталог — це просто таблиця таких пар.

Синтаксис: спочатку оригінал, потім посилання

ln text.t text.lnk          # ЖОРСТКЕ посилання text.lnk на text.t
ln -s text.t text.lnk       # СИМВОЛІЧНЕ (soft) посилання text.lnk → text.t
ln -s /opt/app/v2 current   # типовий прийом: current вказує на активну версію
ln -sf /opt/app/v3 current  # -f: перезаписати існуюче посилання
ls -li                      # -i покаже номери inode: у жорстких посилань вони однакові
readlink -f current         # куди насправді вказує символічне посилання
unlink text.lnk             # видалити посилання (або просто rm text.lnk)

Запам'ятати порядок допомагає cp: «що» → «куди». ln text.lnk text.t з переставленими аргументами спробує створити text.t як посилання на неіснуючий text.lnk і видасть помилку (бо text.t вже існує або text.lnk немає).

locate — пошук у базі

locate text.t шукає не на диску, а в заздалегідь створеній базі імен (оновлюється щодня через cron або вручну sudo updatedb). На мінімальних системах пакет (mlocate/plocate) треба встановити окремо.

Потоки, pipes і перенаправлення#

Кожна програма в Linux при запуску отримує три відкриті потоки з номерами (файлові дескриптори):

0 · stdinСтандартний вхід

Звідки програма читає дані. За замовчуванням — клавіатура.

1 · stdoutСтандартний вивід

Куди пише звичайний результат. За замовчуванням — екран.

2 · stderrПотік помилок

Куди пише повідомлення про помилки. Теж екран, але це окремий потік, тому його можна перенаправити окремо.

ЗаписЩо робить

cmd >> fstdout дописується в кінець файла
cmd < fstdin береться з файла: mysql shop < dump.sql, wc -l < file
cmd 2> fлише помилки (stderr) у файл; звичайний вивід лишається на екрані

Чому порядок у > f 2>&1 важливий

2>&1 означає «направ потік 2 туди, куди зараз указує потік 1». Bash читає перенаправлення зліва направо:

ls /etc /nope > out.txt 2>&1    # 1 → файл; потім 2 → туди ж (файл). Обидва у файлі ✔
ls /etc /nope 2>&1 > out.txt    # 2 → куди зараз 1 (екран); потім 1 → файл. Помилка на екрані ✘
Що означає «Redirect 2>abc»

Потік помилок (stderr, дескриптор 2) записується у файл з назвою abc, файл перезаписується. Звичайний вивід (stdout) не змінюється і йде на екран. Це не «записати у файл 2», не «дописати» (для дописування — 2>>) і не «вивід на вхід команди abc» (це був би pipe).

chmod: числова і символьна форма

Символьна форма: хто (u, g, o, a = усі) + дія (+ додати, - забрати, = встановити точно) + права (r, w, x).

chmod 755 deploy.sh        # числова: rwxr-xr-x, попередні права не враховуються
chmod 644 index.html       # rw-r--r--
chmod u+x script.sh        # символьна: додати власнику виконання, решту не чіпати
chmod +x script.sh         # додати x усім (з урахуванням umask)
chmod a+x script.sh        # додати x усім явно
chmod go-w file            # забрати запис у групи та інших
chmod u=rwx,go=r file      # встановити точно: = 744
chmod o= file              # забрати в інших усе
chmod -R 775 shared/       # рекурсивно для каталогу
chmod --reference=a.txt b.txt   # скопіювати права з іншого файла
stat -c '%a %A %n' file    # подивитися права числом і рядком

umask: звідки беруться права нових файлів

Нові файли створюються з базовими правами 666 (без x — з міркувань безпеки), каталоги — 777. З них вилучаються біти маски umask. Типова маска 022 забирає w у групи та інших:

файл:     666 − 022 = 644  (rw-r--r--)
каталог:  777 − 022 = 755  (rwxr-xr-x)
umask 077 → файли 600, каталоги 700 (приватно)
umask 002 → файли 664, каталоги 775 (спільна робота в групі)

(«Віднімання» тут — це вимикання бітів, а не арифметика: при umask 033 файл отримає 644, а не 633.) Поточна маска: umask, змінити — umask 027.

chown і chgrp: власник і група

sudo chown tony file1 file2          # змінити власника (може лише root)
sudo chown tony:www site/            # власник і група
sudo chown :www site/                # лише група (те саме, що chgrp www site/)
sudo chown -R www-data:www-data /var/www/html   # віддати сайт вебсерверу рекурсивно
chgrp developers report.txt          # змінити групу (власник може, якщо сам у цій групі)

Спеціальні біти: SUID, SGID, sticky

Четверта (найстарша) цифра в записі прав: chmod 4755 — SUID + 755.

БітЧислоСимвольноВидно в ls -lДія
SUID4u+s-rwsr-xr-xфайл виконується з правами власника, а не того, хто запустив. Приклад: /usr/bin/passwd (власник root) пише в /etc/shadow
SGID2g+sdrwxrwsr-xна каталозі: нові файли успадковують групу каталогу. На файлі — виконання з правами групи

Велика літера (S, T) у ls -l означає, що спецбіт встановлено, а відповідного x немає — зазвичай це помилка налаштування.

Приклад: спільна папка для команди

  1. Група і користувачі: groupadd developers, usermod -aG developers dev, usermod -aG developers test.
  2. Каталог: mkdir /home/shared && chgrp developers /home/shared.
  3. Права групі на запис + SGID: chmod 2775 /home/shared (2 = SGID, далі rwxrwxr-x) — усі нові файли належатимуть групі developers.
  4. За потреби sticky bit, щоб не видаляли чужі файли: chmod +t /home/shared (разом — 3775).
  5. Перевірка: ls -ld /home/shared → drwxrwsr-t … developers … /home/shared.

Пам'ять, диск і відомості про систему#

Оперативна пам'ять

$ free -h
               total        used        free      shared  buff/cache   available
Mem:           7.7Gi       2.1Gi       1.2Gi       150Mi       4.4Gi       5.3Gi
Swap:          2.0Gi          0B       2.0Gi
  • free — зовсім не використана пам'ять. Вона мала, і це нормально: Linux використовує вільну пам'ять під кеш диска (buff/cache) і віддає її програмам за потреби.
  • available — скільки реально можна віддати новим програмам. Саме на цю колонку дивіться, оцінюючи нестачу пам'яті.
  • Swap — область підкачки на диску; активне використання swap означає, що RAM не вистачає.

Служби і логи (systemd)#

Демони (служби, що працюють у фоні: nginx, sshd, mysqld) у сучасних дистрибутивах запускає і контролює systemd. Опис служби — «юніт» (/lib/systemd/system/nginx.service).

systemctl status nginx          # стан, PID, останні рядки логу
sudo systemctl start nginx      # запустити зараз
sudo systemctl stop nginx       # зупинити
sudo systemctl restart nginx    # перезапустити (з розривом з'єднань)
sudo systemctl reload nginx     # перечитати конфіг без зупинки (якщо служба підтримує)
sudo systemctl enable nginx     # автозапуск при старті системи (enable --now — і запустити)
sudo systemctl disable nginx    # прибрати з автозапуску
systemctl list-units --type=service --state=running
journalctl -u nginx -f          # лог служби наживо
journalctl -p err -b            # помилки з моменту завантаження
dmesg | tail                    # повідомлення ядра (диски, драйвери, OOM killer)

Не плутайте: start — запустити зараз, enable — запускати при завантаженні. На старих системах — service nginx start і chkconfig.

Вхід по SSH-ключах#

SSH (Secure Shell) — протокол захищеного віддаленого доступу, типово TCP-порт 22. Замінив незахищений Telnet (порт 23), який передавав паролі відкритим текстом. Використовує асиметричне шифрування: приватний ключ лишається у вас, публічний кладемо на сервер у ~/.ssh/authorized_keys.

ssh-keygen -t ed25519 -C "anna@laptop"        # сучасний тип ключа (або -t rsa -b 4096)
ssh-copy-id user@192.168.0.10                 # додати публічний ключ на сервер
# те саме вручну:
cat ~/.ssh/id_ed25519.pub | ssh user@192.168.0.10 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
ssh user@192.168.0.10                         # вхід
ssh -i ~/.ssh/deploy_key -p 2222 user@host    # з указаним ключем і нестандартним портом
ssh user@host 'df -h'                         # виконати одну команду віддалено

Як це працює

  1. Клієнт підключається; сервер показує свій ключ хоста. При першому підключенні ви підтверджуєте його відбиток, і він записується в ~/.ssh/known_hosts. Якщо згодом ключ зміниться — SSH попередить про можливу атаку «людина посередині».
  2. Встановлюється зашифрований канал.
  3. Сервер перевіряє, чи є ваш публічний ключ в authorized_keys, і просить довести володіння приватним: клієнт підписує випадкові дані приватним ключем, сервер перевіряє підпис публічним. Сам приватний ключ мережею не передається.
  • Права обов'язкові: chmod 700 ~/.ssh, chmod 600 ~/.ssh/id_ed25519 ~/.ssh/authorized_keys. Із ширшими правами SSH відмовиться використовувати ключ.
  • Посилення сервера в /etc/ssh/sshd_config: PasswordAuthentication no, PermitRootLogin no, після змін — sudo systemctl reload sshd (не закриваючи поточну сесію, поки не перевірите вхід у новій).
  • Щоб не вводити хост і ключ щоразу — ~/.ssh/config:
Host web
    HostName 203.0.113.10
    User deploy
    Port 2222
    IdentityFile ~/.ssh/deploy_key
# тепер просто: ssh web

Типові помилки#

chmod 777 «щоб точно запрацювало».
Це дає запис усім користувачам — діра в безпеці. Видавайте мінімум: файли 644, каталоги і скрипти 755, секрети 600, а власника задавайте через chown.
У символьній формі a означає «інші».
u — власник, g — група, o — інші, a — усі (all) одразу.
usermod -G group user додає групу.
Без -a він замінює список груп. Правильно: usermod -aG group user.
Скрипт script.sh не запускається «бо нема .exe».
Потрібен атрибут x (chmod +x) і шлях: ./script.sh — поточний каталог не входить у PATH.
cmd1 && cmd2 або cmd1 ; cmd2 передає вивід першої команди другій.
Дані передає лише |. Інші оператори тільки визначають, чи і коли запуститься друга команда.
2> file — «записати у файл 2».
Цифра — номер потоку: 2> перенаправляє stderr (помилки). Усе разом — > file 2>&1 або &> file.
rm -i data видалить каталог з підтвердженням.
-i лише вмикає запитання. Для каталогу все одно потрібен -r (з вмістом) або -d/rmdir (порожній).
rm -r data/* видаляє каталог data.
Він видаляє вміст, а сам data лишається (і приховані файли теж). Каталог разом із вмістом — rm -r data.
apt update оновлює програми.
Він оновлює лише список пакетів. Програми оновлює apt upgrade.
Мало «free» у free -h — сервер задихається.
Linux тримає вільну пам'ять у кеші диска. Дивіться на available і на використання swap.
kill -9 — звичайний спосіб зупинити процес.
Спочатку kill PID (SIGTERM): процес закриє файли і з'єднання. -9 — останній засіб.
Sticky bit ставиться як chmod g+t.
Sticky bit — біт для «інших»: chmod +t dir (або o+t, числом — 1777). У ls -l видно t в останній позиції.
