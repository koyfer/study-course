Linux: основи ОС, команди, користувачі та права доступу

Linux — ОС, на якій працює більшість серверів інтернету. Розбираємо мінімум, без якого DevOps-інженер не відкриє жодного сервера: файлова система, команди, права доступу та вхід по SSH.

Чого ви навчитесь#

  • Пояснити, чим Linux відрізняється від Windows і де шукати файли в дереві каталогів.
  • Впевнено користуватися базовими командами: навігація, файли, процеси, мережа, пакети.
  • Комбінувати команди через pipe |, перенаправлення >, >>, 2>, 2>&1 та ланцюжки ; && ||.
  • Керувати користувачами і групами (useradd, usermod, sudo).
  • Читати й змінювати права: rwx, числа 755, chmod/chown, SUID/SGID/sticky bit.
  • Налаштувати вхід на сервер за SSH-ключем.

Чому саме Linux#

Операційна система (ОС) керує залізом і дає програмам спільні сервіси: процеси, пам'ять, файли, мережу, користувачів. Linux належить до сімейства Unix-подібних (*nix) систем. Ядро анонсував Лінус Торвальдс у 1991 році; з 1992 воно поширюється за ліцензією GNU GPL — тоді ж з'явилися перші дистрибутиви.

  • Безкоштовна і з відкритим кодом. Немає ліцензій на кожен сервер.
  • Домінує на серверах — за даними зі слайдів, близько 70% інтернет-серверів працюють на *nix. Android теж побудований на ядрі Linux.
  • Можна працювати взагалі без графічного інтерфейсу — тільки термінал, що ідеально для серверів.

Структура каталогів#

У Linux «майже все — файл»: звичайні файли, каталоги, пристрої, навіть більшість команд — це програми-файли в /bin.

Команди, які треба знати#

Більшість команд мають ключі (опції), що змінюють поведінку. Довідка: man <команда>.

Символічне посилання — «ярлик», що вказує на ім'я файла (зламається, якщо оригінал видалити). Жорстке — ще одне ім'я для тих самих даних на диску (дані живуть, поки є хоч одне ім'я).

Встановлення і запуск програм

  • Програми встановлюються з репозиторіїв (аналог Google Play): офіційних для дистрибутиву або сторонніх. Встановлювати може лише root (або через sudo).
  • Файл запускається, якщо має атрибут x — розширення не важливе. Скрипт у поточному каталозі запускають так: ./program.sh.
sudo apt install git        # Debian/Ubuntu
sudo yum install git        # RHEL/CentOS
chmod +x program.sh && ./program.sh

Pipes і перенаправлення вводу-виводу#

ps aux | grep apache          # усі процеси apache
ls -a | grep myfile           # файли, в імені яких є myfile
uname -a > mysystem.info      # зберегти інфо про систему у файл
date >> log.txt               # дописати рядок у кінець log.txt

Три стандартні потоки і всі види перенаправлення

Кожна програма має три потоки з номерами (дескрипторами): 0 — stdin (вхід, клавіатура), 1 — stdout (звичайний вивід), 2 — stderr (повідомлення про помилки). Обидва виводи за замовчуванням ідуть на екран, але перенаправляються окремо.

ЗаписЩо робить
cmd1 | cmd2stdout cmd1 → stdin cmd2 (pipe)
cmd > f = cmd 1> fstdout у файл, файл перезаписується
cmd >> fstdout дописується в кінець файла
cmd < fstdin береться з файла (напр. mysql db < dump.sql)
cmd 2> fлише помилки (stderr) у файл f; звичайний вивід лишається на екрані
cmd > f 2>&1 або cmd &> fі stdout, і stderr в один файл
cmd 2> /dev/nullвикинути помилки («чорна діра»)
cmd | tee fпоказати на екрані і записати у файл
find / -name "*.conf" 2> /dev/null     # шукати, не засмічуючи екран «Permission denied»
./deploy.sh > deploy.log 2>&1          # повний лог: вивід + помилки

Ланцюжки команд: ; & && ||

ЗаписКоли виконується cmd2
cmd1 ; cmd2завжди, після cmd1 (дані не передаються)
cmd1 && cmd2лише якщо cmd1 успішна (код 0)
cmd1 || cmd2лише якщо cmd1 завершилась помилкою
cmd1 & cmd2одразу: cmd1 іде у фон (background)
mkdir -p /opt/app && cd /opt/app          # перейти, тільки якщо каталог створено
ping -c1 db.local || echo "БД недоступна"   # повідомлення лише при помилці

Не плутайте: тільки | передає дані між командами; ;, &&, || керують лише порядком запуску.

Користувачі та групи#

Linux — повністю багатокористувацька ОС. Кожен користувач і група мають ім'я та числовий ідентифікатор (UID/GID). Користувач має одну основну (primary) групу і може мати кілька додаткових (secondary).

  • /etc/passwd — облікові записи; /etc/shadow — хеші паролів (читає лише root); /etc/group — групи.

Рядок /etc/passwd має 7 полів через двокрапку: tony:x:1001:1001:Tony:/home/tony:/bin/bash — ім'я, x (пароль винесено в /etc/shadow), UID, GID, коментар, домашній каталог, оболонка. Колись хеш пароля зберігався прямо тут, але /etc/passwd читають усі, тому хеші перенесли в /etc/shadow (права лише для root).

groupadd developers                 # створити групу
grep developers /etc/group          # перевірити, що група існує
useradd -G developers vivek         # користувач з додатковою групою
passwd vivek                        # задати пароль
id vivek                            # UID, GID і всі групи
useradd -g developers tony          # -g = основна група
usermod -a -G ftp tony              # -a -G = ДОДАТИ ще одну групу
usermod -g www tony                 # змінити основну групу
chage -d 0 tony                     # змусити змінити пароль при вході
usermod -L tony                     # заблокувати пароль
usermod -aG wheel tony              # CentOS: група wheel = права sudo
Пастка

usermod -G ftp tony без -a замінить усі додаткові групи користувача однією ftp. Для додавання завжди пишіть -aG.

Права доступу до файлів#

Кожен файл має власника (u — user), групу (g) і всіх інших (o — others). Для кожної категорії — три права: r (read, 4), w (write, 2), x (execute, 1). Число для категорії — сума прав.

chmod: абсолютна і відносна форма

chmod 755 deploy.sh        # абсолютно: rwxr-xr-x (попередні права не враховуються)
chmod 644 index.html       # rw-r--r-- — типово для вебфайлів
chmod u+x script.sh        # відносно: додати власнику виконання
chmod go-w file            # забрати запис у групи та інших
chmod a+r file             # a = all (усім) — додати читання
chmod -R 775 opencart      # рекурсивно для каталогу

chown / chgrp: власник і група

chown tony file1 file2           # змінити власника
chgrp sales /home/sales/*        # змінити групу
chown -R tony:www site/          # власник і група рекурсивно
chown -R apache:apache opencart  # типово: віддати сайт вебсерверу

Спеціальні біти

SUID — chmod u+sЗапуск від імені власника

Напр. /usr/bin/passwd має s: звичайний користувач змінює пароль, а програма пише в /etc/shadow з правами root.

SGID на каталозі — chmod g+sСпільна група

Нові файли в каталозі успадковують групу каталогу — зручно для спільної папки команди.

Sticky bit — chmod +tВидаляє лише власник

У каталог можуть писати всі, але видалити файл може тільки його власник (як /tmp).

«Темний каталог»: chmod a-r+x darkcat — у каталог можна зайти (cd) і прочитати файл, якщо знаєш його ім'я, але ls видасть Permission denied. Це показує, що r для каталогу — це право бачити список, а x — право входити.

Приклад: спільна папка для команди

  1. Група і користувачі: groupadd developers, useradd -G developers dev, useradd -G developers test.
  2. Каталог: mkdir /home/shared && chgrp developers /home/shared.
  3. Права групі на запис + SGID: chmod 2775 /home/shared (2 = SGID, далі rwxrwxr-x).
  4. За потреби sticky bit, щоб не видаляли чужі файли: chmod +t /home/shared.

Вхід по SSH-ключах#

SSH (Secure Shell) — протокол захищеного віддаленого доступу, типово TCP-порт 22. Використовує асиметричне шифрування: приватний ключ лишається у вас, публічний кладемо на сервер у ~/.ssh/authorized_keys.

ssh-keygen -t rsa -b 4096                     # створити пару ключів
ssh-copy-id user@192.168.0.10                 # додати публічний ключ на сервер
# те саме вручну:
cat ~/.ssh/id_rsa.pub | ssh user@192.168.0.10 "cat >> ~/.ssh/authorized_keys"
ssh -i ~/.ssh/id_rsa user@192.168.0.10        # вхід з указаним ключем

На сервері шлях до ключів задає AuthorizedKeysFile .ssh/authorized_keys у /etc/ssh/sshd_config.

Віртуалізація

Для практики Linux зазвичай ставлять у віртуальну машину (наприклад, VirtualBox): гіпервізор відокремлює залізо від гостьових ОС і дозволяє запускати кілька систем одночасно. Детально — у лекції 9.

Типові помилки#

chmod 777 «щоб точно запрацювало».
Це дає запис усім користувачам — діра в безпеці. Видавайте мінімум: файли 644, каталоги і скрипти 755, а власника задавайте через chown.
У відносній формі a означає «інші».
u — власник, g — група, o — інші, a — усі (all) одразу.
usermod -G group user додає групу.
Без -a він замінює список груп. Правильно: usermod -aG group user.
Скрипт script.sh не запускається «бо нема .exe».
Потрібен атрибут x (chmod +x) і шлях: ./script.sh — поточний каталог не входить у PATH.
cmd1 && cmd2 або cmd1 ; cmd2 передає вивід першої команди другій.
Дані передає лише |. Інші оператори тільки визначають, чи і коли запуститься друга команда.
2> file — «записати у файл 2».
Цифра — номер потоку: 2> перенаправляє stderr (помилки). Усе разом — > file 2>&1 або &> file.
Sticky bit ставиться як chmod g+t.
Sticky bit — це біт для «інших»: chmod +t dir (або o+t, числом — 1777). У ls -l видно t в останній позиції.
